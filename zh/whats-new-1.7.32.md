# tinystruct 1.7.32 新特性

本文档重点介绍了 tinystruct 1.7.32 版本中引入的新特性、改进和变更。

> 另请参阅：[1.7.31 新特性](whats-new-1.7.31.md)，了解支持 PostgreSQL SSL/Schema 和性能优化的上一个版本。

---

## 1.7.32 亮点

- **扩展的数据类型支持**：`FieldType` 新增了 `UUID` 和 `JSONB` 字段类型，使得在 POJO 生成器和 ORM 层能够映射原生的 PostgreSQL 类型。
- **`FieldInfo` 重构为纯 POJO**：`FieldInfo` 不再继承 `HashMap`。它现在是一个强类型的、高性能的值对象，具有明确的字段并保留了兼容性门面。
- **统一的生成器类型处理**：所有 POJO 生成器（MySQL、PostgreSQL、SQLite、H2、MSSQL）共享相同的扩展 `FieldType` 常量，确保在各个数据库引擎中保持一致的代码生成。

---

## 主要新特性与增强

### 1. 新增 `FieldType` 常量：`UUID` 和 `JSONB`

`FieldType` 增加了两个新常量，以提升对 PostgreSQL 原生列类型的第一方支持：

| 常量 | SQL 类型 | Java 映射 | 说明 |
|---|---|---|---|
| `FieldType.UUID` | `UUID` | `String` | 通过 `Types.OTHER` 映射；被 PostgreSQL UUID 列使用 |
| `FieldType.JSONB` | `JSONB` | `String` | 映射方式与 `FieldType.JSON` 相同；PostgreSQL 二进制 JSON |

这些常量现在被 `PostgreSQLGenerator` 以及所有继承自共享类型注册表的生成器识别，确保在生成的 POJO 类中准确地生成 Java 类型。

#### 示例 — 为 UUID 列生成的字段

```java
// 1.7.32 之前：UUID 列作为 Object 生成，或回退为 String
// 1.7.32 之后：具备正确的类型和注解
@Column(name = "id", type = "UUID")
private String id;
```

---

### 2. `FieldInfo` 重构：移除 HashMap 依赖

`FieldInfo` 经过了彻底重新设计，现在是一个适当的值对象。它不再继承 `HashMap<String, Object>`，从而消除了相关的内存开销，并消除了将元数据当作通用映射处理而导致的微妙错误。

#### 变更内容

| 之前 (≤ 1.7.31) | 之后 (1.7.32) |
|---|---|
| 继承自 `HashMap<String, Object>` | 仅实现 `Serializable` |
| 列属性存储为映射的键值对 | 使用明确的 `private` 字段及访问器 |
| 属性访问没有类型安全保障 | 完全类型化的 getter/setter |
| 没有定义序列化 UID | 定义了 `serialVersionUID = 1L` |

#### 明确类型化的关键字段

```java
public class FieldInfo implements Serializable {
    private String name;           // 逻辑字段名称
    private String columnName;     // 实际的数据库列名称
    private Object value;          // 行值
    private FieldType type;        // 解析出的 FieldType
    private int length;            // 列最大长度
    private boolean autoIncrement; // 自动递增标志
    private boolean autoGenerated; // UUID 自动生成标志
    // ...
}
```

#### 保留兼容性门面

保留了字符串键方法（`append(String, Object)`、`set(String, Object)`、`get(String)`）作为兼容性门面，以使现有使用动态属性访问的代码可以继续工作而无需修改。

#### 默认时间戳回退值

当时间戳类型字段的值为空或未设置时，现在使用定义良好的占位时间戳（`1982-03-20 00:00:00.0`），这取代了以前未定义的行为。

---

### 3. 统一 POJO 生成器类型处理

所有五个 POJO 生成器均已更新为使用扩展后的共享 `FieldType` 常量：

| 生成器 | 数据库 |
|---|---|
| `MySQLGenerator` | MySQL / MariaDB |
| `PostgreSQLGenerator` | PostgreSQL |
| `SQLiteGenerator` | SQLite |
| `H2Generator` | H2 (嵌入式) |
| `MSSQLGenerator` | Microsoft SQL Server |

以前，每个生成器都会重复自身的类型映射逻辑并带有轻微的不一致。它们现在统一使用 `FieldType` 注册表，确保类型名称和 Java 映射是相同的，无论目标数据库是什么。

---

### 4. 改进 `FieldInfo` 测试覆盖率

增加了一个全面的 JUnit 5 测试类 (`FieldInfoTest`)，涵盖：

- 构造函数变体（无参数、仅名称、名称+值）。
- 所有类型化 getter/setter 的全覆盖测试。
- `autoIncrement` 和 `autoGenerated` 标志的行为。
- 默认时间戳占位符的使用。
- 兼容性门面方法 (`append`、`set`、`get`)。

## 迁移指南

### 更新到 1.7.32

将您的 `pom.xml` 依赖更新至 `1.7.32` 版本：

```xml
<dependency>
    <groupId>org.tinystruct</groupId>
    <artifactId>tinystruct</artifactId>
    <version>1.7.32</version>
</dependency>
```

#### `FieldInfo` 迁移注意事项

如果您的代码**直接将 `FieldInfo` 强制转换为 `Map`**，或在 `FieldInfo` 实例上调用特定的 `Map` 方法（如 `entrySet()`、`containsKey()` 等），则必须更新这些调用处：

```java
// 之前（无法再编译 —— FieldInfo 已不再是 Map）
Map<String, Object> map = (Map<String, Object>) fieldInfo;
Object val = map.get("value");

// 之后 —— 直接使用类型化访问器
Object val = fieldInfo.getValue();
```

所有通过标准的 `append`/`set`/`get` 门面使用 `FieldInfo` 的代码都保持源代码层面兼容。
