# tinystruct 1.7.34 新特性

本文档重点介绍了 tinystruct 1.7.34 版本中引入的新特性、改进和变更。

> 另请参阅：[1.7.32 新特性](whats-new-1.7.32.md)，其中介绍了 UUID/JSONB 支持以及 FieldInfo 重构等。

---

## 1.7.34 亮点

- **枚举集合参数支持**：`@Action` 方法现在可以接收 `List<EnumType>` 参数 —— 逗号分隔的字符串会自动转换为枚举集合。
- **基于注解的 ORM 映射**：新增 `@Table`、`@Id` 和 `@Column` 注解，支持声明式的、代码优先的 POJO 映射，而无需依赖 XML 配置。
- **表自动创建功能**：当在映射实体上设置了 `autoCreate` 标志时，ORM 层现在可以在首次使用时自动创建表。
- **`id` 属性重命名**：`FieldInfo` 中含糊不清的 `id` 属性已被拆分为更明确的 `autoIncrement` 和 `autoGenerated` 字段，以提高清晰度。
- **生成器注解模式**：所有 POJO 生成器都支持新的注解输出模式，可直接在生成的源文件中生成 `@Table`/`@Id`/`@Column` 注解。
- **移除 Fat JAR**：默认的 fat JAR 制品已被放弃，转而采用更精简、由依赖管理的发行版。

## 主要新特性与增强

### 1. 枚举集合参数转换

声明了 `List<E extends Enum<E>>` 参数的 `@Action` 方法现在可以在 CLI 和 HTTP 环境中无缝工作。框架会自动分割逗号分隔的字符串值，并将每个分词转换为目标枚举常量。

#### 示例

```java
public enum Role { ADMIN, USER, GUEST }

@Action(value = "set-roles", description = "Assign roles to a user",
        arguments = { @Argument(key = "roles", description = "Comma-separated roles") })
public String setRoles(List<Role> roles) {
    return "Assigned: " + roles;
}
```

```bash
# CLI 用法
bin/dispatcher set-roles --roles ADMIN,USER

# HTTP 用法
GET /set-roles?roles=ADMIN,USER
```

这两种调用都会产生 `Assigned: [ADMIN, USER]`。

---

### 2. 基于注解的 ORM 映射（`@Table`、`@Id`、`@Column`）

通过三个新注解，您可以直接在 POJO 类上定义完整的 ORM 映射，这在反映流行 JPA 做法的同时，依然保留在 tinystruct 生态系统中。

| 注解 | 目标 | 用途 |
|---|---|---|
| `@Table` | 类 | 将类映射到数据库表 |
| `@Id` | 字段 | 标记主键字段 |
| `@Column` | 字段 | 将字段映射到特定的列名称和类型 |

#### 示例

```java
import org.tinystruct.data.component.Table;
import org.tinystruct.data.component.Id;
import org.tinystruct.data.component.Column;

@Table(name = "users")
public class User extends AbstractData {

    @Id
    @Column(name = "id", type = "INT", autoIncrement = true)
    private int id;

    @Column(name = "username", type = "VARCHAR", length = 100)
    private String username;

    @Column(name = "email", type = "VARCHAR", length = 255)
    private String email;

    // getters and setters...
}
```

当存在注解时，XML 映射文件现在变为可选的。

---

### 3. 表自动创建功能

当在 `@Table` 注解上设置 `autoCreate = true` 时，tinystruct 会在首次访问该实体时检查映射的列并执行 `CREATE TABLE IF NOT EXISTS` DDL 语句。这消除了在开发和测试期间的手动架构设置。

```java
@Table(name = "sessions", autoCreate = true)
public class Session extends AbstractData {
    @Id
    @Column(name = "id", type = "VARCHAR", length = 64)
    private String id;

    @Column(name = "user_id", type = "INT")
    private int userId;

    @Column(name = "expires_at", type = "TIMESTAMP")
    private java.time.LocalDateTime expiresAt;
}
```

> **注意：** 自动创建是需要明确启用的，并且默认情况下处于禁用状态。建议仅在开发或测试环境中使用。

---

### 4. `FieldInfo` 属性重命名

为了提高代码清晰度，`FieldInfo` 上以前含糊不清的 `id` 布尔属性已被两个截然不同的字段取代：

| 旧属性 | 新属性 | 含义 |
|---|---|---|
| `id = true` (自动递增) | `autoIncrement = true` | 该列是数据库管理的自动递增主键 |
| `id = true` (UUID) | `autoGenerated = true` | 值为应用程序生成的（如 UUID） |

这一变化使 `FieldInfo` 的语义与新的 `@Id` 注解保持一致，并消除了旧 `id` 标志被重载的含义。

---

### 5. 生成器注解模式

所有五个 POJO 生成器现在都支持注解输出模式。启用后，生成的 Java 源码将包含 `@Table`、`@Id` 和 `@Column` 注解，使得输出结果能够直接与新的基于注解的 ORM 层搭配使用。

```bash
# 从 MySQL 表生成带注解的 POJO
bin/dispatcher generate --table users --driver mysql --annotations
```

## 迁移指南

### 更新到 1.7.34

更新您的 `pom.xml` 依赖：

```xml
<dependency>
    <groupId>org.tinystruct</groupId>
    <artifactId>tinystruct</artifactId>
    <version>1.7.34</version>
</dependency>
```

### `FieldInfo` 迁移

如果您直接在 `FieldInfo` 实例上设置了 `id` 属性，请更新为使用新的命名字段：

```java
// 之前 (≤ 1.7.32)
fieldInfo.setAutoIncrement(true);  // was: fieldInfo.put("id", true)

// 之后 (1.7.34)
fieldInfo.setAutoIncrement(true);  // 自动递增主键
fieldInfo.setAutoGenerated(true);  // UUID / 应用程序生成的值
```

通过标准的 `append`/`set`/`get` 兼容门面来访问 `FieldInfo` 的代码在源代码层面保持兼容，无需任何更改。
